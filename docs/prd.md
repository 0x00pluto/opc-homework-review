产品需求文档 (PRD)产品名称：AI 作业智能评审与反馈系统 V1.0 (AI-Homework Review & Feedback Engine)一、 文档概述1.1 产品背景与目标本系统专为 OPC（One Personal Company，一人公司）超级个体训练营设计。针对大龄（35岁以上）、面临职业转型、需要极大心理建设和实操指导的独立创作者及自由职业者群体，提供高效、有温度的作业批改服务。系统旨在通过引入异步多线程的 AI Agent 架构，替代传统人工批阅或依赖飞书等外部协作文档的繁琐流程，实现作业自动抓取、智能逻辑比对、低质内容过滤及高标准情绪价值反馈，最终形成完整的闭环数据沉淀。1.2 核心业务指标并发处理能力： 支持单次最多唤起 5 个独立 Agent 进程异步处理作业，前台零阻塞。反馈标准化率： 100% 遵循“正向鼓励为主 + 1至2个直接可落地操作”的评审基调。数据内化率： 摆脱对第三方表格的依赖，实现全流程数据本地化（SQLite/关系型数据库）存储与流转。二、 用户角色 (RBAC)为了扩充系统体量，我们需要定义多角色权限体系：系统管理员 (Admin)： 负责整体系统参数配置、AI Agent 调度监控、大模型 API 密钥管理及底层日志查询。教研专家/讲师 (Instructor)： 负责维护知识库（如《OPC产品说明手册》、每日任务要求）、二次审核 AI 的判卷结果（等待审核状态的作业）。助教 (Teaching Assistant)： 负责查看作业进度大盘，手动干预异常作业流程。系统后台引擎 (AI Agent Worker)： 虚拟角色，负责执行底层数据抓取、推理和回写任务。三、 系统模块划分 (大而全的页面规划)为满足软著对代码量和页面数的要求，系统拆分为以下 六大核心子系统（包含对应的前端页面）：模块一：作业数据总线中心 (Homework Data Center)取代原飞书多维表格[工作日报中心]1.1 作业大厅 (UI)： 极简设计的高信息密度表格，展示所有学员提交的作业记录。支持按状态（待处理、处理中、等待审核、已完成）、提交时间多维检索。1.2 作业详情沙盒 (UI)： 左侧展示作业原文内容（通过解析链接抓取的内容或原始富文本），右侧预留 AI 反馈区及人工批注区。1.3 批次导入与对接设置： 支持通过 CSV/Excel 批量导入作业源数据，或配置 Webhook 自动接收作业提交事件。模块二：AI 调度与并发管理引擎 (Agent Dispatch System)软著的核心技术亮点2.1 Agent 运行态势感知盘 (UI)： 电影级质感的深色数据看板（Dashboard）。实时展示当前活跃的 Agent 数量（上限 5 个）、每个 Agent 的处理耗时、成功/失败率。2.2 任务队列管理 (UI)： 采用消息队列机制，展示“等待判作业”的排队列表，禁止阻塞当前 UI 线程。支持管理员一键“熔断”或“重试”特定任务。模块三：知识库与标准容器 (Knowledge & Standards Base)3.1 核心概念词典： 结构化录入《OPC产品说明手册》，作为 Agent 执行时的 RAG（检索增强生成）前置上下文。3.2 任务规则引擎 (UI)： 允许讲师动态配置 [Day2-任务说明] 等不同阶段的作业要求。3.3 评审基调调节器 (Prompt Manager)： 图形化界面管理 System Prompt。固化“以正向鼓励为主”、“提供可操作建议”等规则，防止 Prompt 漂移。模块四：评审结果工作流处理 (Feedback Workflow)4.1 待审核反馈池 (UI)： 集中展示 AI 判定完毕并更改状态为 [等待审核] 的记录。4.2 质量风控告警： 针对被 AI 识别为“逻辑前后矛盾”或“未经人工检查的低质 AI 生成内容”，打上红色高亮 Tag，强制要求讲师介入。4.3 终审与发布： 讲师确认无误后，点击发布。系统底层生成结构化的 [作业问题反馈] 记录。模块五：学员画像与成长轨迹 (Student CRM)5.1 学员档案卡： 记录学员背景（重点关注其转型期痛点），历史作业评分趋势图。5.2 常见问题雷达图： 统计所有学员在作业中最常出现的错误点，反哺教研内容优化。模块六：系统与环境设置 (System Config)6.1 API 路由与鉴权配置： 大模型接口选择（如豆包、GPT 等）、并发阈值（锁定最大 5 并发）配置。6.2 数据库连接与备份： SQLite 文件的本地备份与导出策略。四、 核心业务流程描述 (AI Agent 工作流)以下为核心的 [作业提交 -> AI 评审 -> 结果回写] 自动化流水线：触发阶段： 系统轮询本地数据库（如表 tb_homework），检索字段 status = 'WAITING_REVIEW' 的记录。分配阶段： 主控程序检查当前活动 Agent 线程数。若 $< 5$，则派发任务；若满载，则进入无阻塞排队状态。抓取阶段 (Agent Action 1)： Agent 读取目标记录的 homework_link 字段，执行静默爬取或内容提取（替代飞书文档直读），将内容转为纯文本或 Markdown。推理阶段 (Agent Action 2)：注入上下文： 提取知识库中的《OPC产品说明手册》与《Day2-任务说明》。双重校验：质检指令： 分析是否存在前后逻辑矛盾、是否具极高 AI 痕迹。共情指令： 针对大龄/转型学员，必须生成具有安抚性和情绪价值的正向起手式。生成反馈： 提炼 1-2 个具体可动手的行动点。回写阶段 (Agent Action 3)：将生成的反馈内容以富文本格式写入本地数据库表 tb_feedback，并关联当前作业 ID。将原作业记录的状态更新为 status = 'PENDING_AUDIT'（等待审核）。Agent 线程释放，主线程全过程不锁死。五、 数据库核心表结构设计 (SQLite 适用)为满足软著技术说明要求，需体现数据库结构：表 1：opc_homework_records (作业记录表)id (主键)student_id (学员外键)homework_link (原作业飞书链接或文本)status (状态: WAITING_REVIEW, PROCESSING, PENDING_AUDIT, COMPLETED)submission_time (提交时间)表 2：opc_ai_feedbacks (AI反馈表)id (主键)homework_id (关联作业表)feedback_content (详细反馈内容，建议深度和改进方向)is_low_quality (布尔值，是否判定为低质AI内容)generation_time (生成时间)表 3：sys_agent_logs (Agent 运行日志表)log_id, agent_thread_id, target_homework_id, execution_time, result_state

# AI作业智能评审与反馈系统 V1.0
> PRD 草稿 v0.1 — 待确认补充

---

## 一、产品定位与设计目标

### 1.1 产品定位
面向OPC（一人公司）学员的作业评审辅助平台。AI承担初评工作，老师承担最终审核与质量守门角色，学员通过平台完成作业提交、反馈查看与修改迭代。

### 1.2 核心价值
- **降低老师重复性判作业成本**：AI初筛+老师复审，减少逐字阅读时间
- **学员获得即时反馈**：提交后即可看到AI评审草稿（经老师审核后正式发布）
- **可追溯的成长轨迹**：记录学员完整作业历史与能力变化

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 学员 | OPC学员，拥有独立账号，提交作业、查看反馈、修改再提交 |
| 老师 | 布置作业、审核AI草稿、管理知识库、查看工作量统计 |
| 教务/管理层 | 查看老师工作量报表（当前仅展示老师个人数据） |

## 二、系统架构

### 2.1 技术选型
- **数据库**：SQLite（本地持久化）
- **文件存储**：本地文件系统（支持 PDF/Word/图片原始文件存储）
- **AI评审模块**：独立Agent线程，实时读取知识库内容作为参考上下文
- **前端**：Web端（学员端 + 老师端）

### 2.2 系统模块划分

```
AI作业智能评审与反馈系统
├── 认证与权限模块
│   ├── 学员账号注册/登录
│   ├── 老师账号登录
│   └── 角色权限校验
├── 班级管理模块
│   ├── 班级创建/编辑/删除
│   ├── 学员绑定班级（一学员一班级，固定绑定）
│   └── 学员学号/密码重置
├── 作业管理模块（老师端）
│   ├── 布置作业（按班级下发）
│   ├── 设置截止时间（默认当天20:00）
│   ├── 超时提醒触发
│   └── 作业删除/修改
├── 作业提交模块（学员端）
│   ├── 多格式提交（纯文本 / PDF / Word / 图片）
│   ├── 截止时间前自动提醒
│   ├── 超时仍可提交（老师决定是否收取）
│   └── 提交后状态变更
├── AI评审模块
│   ├── 触发条件：新作业提交 / 学员修改后再提交

│   ├── 输出结构化评审草稿
│   └── 超时/异常 → 任务挂起，等待老师重评
├── 老师审核模块
│   ├── 查看AI评审草稿

│   ├── 系统自动写入学员作业文档

│   └── 状态更新：[等待判作业] → [等待审核] → [已发布]
├── 学员修改迭代模块
│   ├── 学员查看反馈
│   ├── 修改后再次提交 → 触发AI重新评审
│   └── 老师审核流程同第一轮
├── 知识库管理模块
│   ├── 知识库文档维护（OPC手册/任务说明/标准答案）
│   ├── 文档版本管理
│   └── 老师（教务）可编辑
├── 成长轨迹模块（学员端）
│   ├── 作业完成历史
│   ├── 得分趋势图
│   ├── 能力雷达图/能力提升建议
│   └── 系统自动生成，无需人工填写

    ├── 本周审核作业数量
    ├── 平均审核时长
    ├── 打回重评比例
    └── 仅展示老师个人数据
```

## 三、数据模型设计

### 3.1 核心实体

```
【班级】Class
- id (PK)
- name: 班级名称
- created_at / updated_at

【学员】Student
- id (PK)
- username / password_hash（加密）
- student_number（唯一）
- class_id (FK → Class)
- created_at

【老师】Teacher
- id (PK) / username / password_hash / created_at

【知识库文档】KnowledgeDoc
- id (PK) / title / category（OPC手册/任务说明/标准答案）
- content / version / created_at / updated_at

【作业模板】AssignmentTemplate
- id (PK) / title / description / deadline
- class_id (FK) / created_by (FK → Teacher) / created_at

【作业记录】AssignmentRecord
- id (PK) / template_id (FK) / student_id (FK)
- status（状态枚举）
- submission_content / submission_type（text/pdf/word/image）
- submitted_at / ai_review_content / teacher_review_content
- review_type（ai_only/human_only/ai_then_human）
- teacher_id (FK) / reviewed_at / published_at
- created_at / updated_at

【评审历史】ReviewHistory
- id (PK) / record_id (FK) / reviewer_type（ai/teacher）
- content / action（auto_review/re_review/manual_edit/approve）
- created_at
```

### 3.2 作业状态机

```
[待布置] → 老师布置作业
[已布置] → 学员提交
[等待判作业] → AI评审完成
[等待审核] → 老师审核通过
[已发布] → 学员修改
[已修改] → AI重新评审
[等待审核]（循环）→ ……
[已发布]（最终）
```

## 四、核心业务流程

### 4.1 第一轮

1. 老师创建作业模板 → 选择班级 → 设置截止时间 → 发布
2. 系统自动向班级所有学员生成作业记录（状态：[已布置]）
3. 截止时间前 → 系统自动发送提醒
4. 学员登录 → 提交作业（文本/文件）→ 状态变为 [等待判作业]
5. AI Agent 自动触发评审 → 生成评审草稿 → 状态变为 [等待审核]
6. 系统提醒老师有新作业待审核
7. 老师审核AI草稿：批准 / 打回重评（附加人工要求）/ 人工直接修改
8. 老师确认 → 状态变为 [已发布]
9. 系统自动将最终评审内容写入学员作业文档
10. 学员收到通知 → 查看反馈

### 4.2 修改迭代（第二轮及以后）

1. 学员查看 [已发布] 反馈后 → 修改作业文档
2. 学员再次提交 → 状态变为 [已修改]
3. AI 自动重新评审 → 状态变为 [等待审核]
4. 重复第一轮 7-10 步骤

### 4.3 异常处理

| 场景 | 处理方式 |
|------|---------|
| 作业截止未提交 | 系统自动提醒，仍可超时提交 |
| AI评审超时 | 任务挂起，老师手动触发重评 |
| AI输出格式异常 | 识别失败，标记通知老师人工处理 |
| 知识库文档读取失败 | 评审失败，通知知识库管理员 |
| 学员重复提交 | 以最新版本为准，历史保留在ReviewHistory |
